# Excel 收款匹配快速处理设计

## 目标

把医保正收款与非医保负收款匹配从 Codex 自由执行改为确定性的本地处理，使 33,002 行规模的工作簿在 10 分钟内完成，并保证生成文件可以通过企业微信回传。

## 处理规则

- 工作簿只读取一次，所有记录、候选组和校验结果保存在内存中。
- 以“日期 + 金额绝对值（精确到分）”分组。
- 医保正收款与非医保负收款按时间升序一对一匹配；同额多条时优先最早记录。
- 如果存在同日同额非医保正收款，按配对顺序逐条消费非医保正收款；每条源流水（医保正、非医保负或非医保正）最多属于一个组：
  - 医保正收款更早：保留医保正、非医保负和该非医保正记录。
  - 非医保正收款更早：剔除整个匹配组。
  - 两者时间相同：不视为“非医保正收款更早”，保留该匹配组。
- 结果按匹配组集中展示，组内按日期、时间升序排列。
- 原始工作表保持不变，只替换或新增“匹配结果”工作表。

## 性能与校验

- 使用一次 `openpyxl.load_workbook`，禁止重复打开工作簿。
- 匹配完成后在内存校验：金额绝对值一致、角色完整、组内顺序正确、被剔除组不出现在结果中。
- 只执行一次 `save` 导出。
- 只渲染和抽查“匹配结果”页，不渲染完整原始数据页。
- 日志分别记录读取、匹配校验、导出和总耗时。

## 服务集成

- 新建独立处理模块，由客服文件流程按扩展名、字段和用户指令共同判定是否启用。
- 不符合规则或缺少依赖时继续使用现有 Codex CLI 流程。
- 每次文件处理创建独立输出目录；文件回复只扫描本次请求目录，避免并发任务覆盖或串发附件。
- 文件回复增加“本次请求最近生成文档”兜底扫描，覆盖模型未在最终文本中明确写出文件路径的情况。

## 错误处理

- 缺列、日期/时间无效、金额无效时返回明确错误，不覆盖源文件。
- 导出使用新的描述性文件名。
- 任何本地处理失败都记录原因并回退到现有流程，不中断客服服务。
